# ARCHITECTURE — v0.1

## Current, built
`index.html` static mobile-first UI → `app.js` data validator, derived metrics, entry/filters/agent notes, JSON import/export → browser `localStorage` key `j-nba-prop-intel-v0.1` → `styles.css` responsive design. No dependencies, external API calls, authentication or servers. ~~Illustrative records seeded at first use.~~ *(Superseded 2026-11-11 session 5: no records are seeded; the board starts empty and `load()` drops saved demo records.)* Data is device-local; a deleted profile or different phone will not see it. Static sample numbers are synthetic.

### Data schema
JSON root `schema: "j-nba-prop-intel"`, `version: "0.1"`, `exportedAt`, `records[]`.
Each record: `id`, `demo`, `player`, `team`, `opponent`, `gameDate`, `market`, `side`, `line`, `odds`, `sportsbook`, `oddsCaptured`, `oddsSource`, `recentGames` (newest first), `statSource`, `roleNotes`, `injuryStatus`, `injuryChecked`, `injurySource`, `matchupNotes`, `verdict`, `reviewer`, `reason`, `reviews[]`, `createdAt`, `updatedAt`.
Each review: `id`, `role`, `verdict`, `agent`, `source`, `notes`, `timestamp`.

### Derived calculations
- `implied(-110) = 110/(110+100) = 52.38%`, `implied(+115) = 100/215 = 46.51%`. These are *raw* bookmaker implied percentages and include vig.
- Over hit only for `value > line`, under hit only `value < line`; `value === line` is a push excluded from the decided-game denominator. Last-N windows use up to N supplied observations. DNPs must be omitted by data entry.
- Checklist-complete flags only indicate **completeness of required fields and recency**, *not* independent verification of the content. In particular, URL presence does not prove provenance, and agent reviews can still be wrong.

## Proposed production, not built
- Auth-gated backend + Postgres for normalized immutable per-provider snapshots and research runs.
- BALLDONTLIE or The Odds API keyed on server side for current NBA odds and logs, respecting provider access tiers. NBA injury page revision captured with date/time and URL.
- Data validation/reconciliation layer, source-specific throttles and caching, freshness rules, alerts for changes, deterministic statistical calculations, and blinded historical backtesting.
- Hub integration: opt-in navigation entry + project summary; full records remain in the NBA app. Authorized Zeus/agents access an audited restricted research API (never personal Hub data by default).
- Version control in a project-specific repository if available; otherwise preserve an immutable archive with checksums until migration.

`odds-adapter.js` (pure functions, no network, no keys; `module.exports` in Node, `window.PropIntelAdapter` in a browser) defines how provider payloads become records. Network fetching must live in a separate server-side/CLI wrapper so keys never enter this public repo or the browser.

### Quote record (The Odds API v4 `GET /v4/sports/basketball_nba/events/{eventId}/odds?regions=us&markets=player_points,player_rebounds,player_assists&oddsFormat=american`)
Required, never defaulted: `provider`, `book`, `event{id,home_team,away_team,commence_time}`, `player`, `market`, `side`, `line`, `price`, `source_url` (request URL, **no apiKey**), `collected_at` (our request time), plus `provider_updated_at` (the market-level `last_update`, which the provider says is authoritative; bookmaker-level `last_update` is deprecated). Mapping from the provider's outcome: `name`→`side` (Over/Under), `description`→`player`, `point`→`line`, `price`→`price`, market `key`→`market`.
Behavior: decimal prices, missing player/last_update, unsupported sides and unmapped market keys are **rejected with a reason**, not repaired. `findQuotes` matches exact normalized player name + market + side + line only (no fuzzy name, no nearest line). Status `OK` (fresh ≤30 min by provider `last_update`), `STALE`, or `UNAVAILABLE` ("No verified quote available"). Only `player_points`, `player_rebounds`, `player_assists` are mapped because only they were seen in provider docs; `3PT made`, combos, steals, blocks stay UNMAPPED until keys are confirmed with `GET /v4/sports/basketball_nba/events/{id}/markets`.

### Game-log sample (BALLDONTLIE `GET https://api.balldontlie.io/v1/stats?player_ids[]=..&seasons[]=..`, header `Authorization: <key>`; requires paid ALL-STAR or higher)
Output: `games[{date,game_id,minutes,value}]` newest first, `selected_count`, `window{newest,oldest}`, `excluded[]` with reasons, `source_url`, `collected_at`, `status` OK|PARTIAL|UNAVAILABLE. Provider docs state stats carry **no DNP/inactive classification** and that zero or missing minutes do not establish non-participation, so rows without positive minutes are excluded as *participation unverified* (never scored as 0). Non-final games are excluded. Pushes (value == line) are excluded from hit-rate denominators, matching `performance()` in `app.js`.

### Cost model (The Odds API, verified in provider docs): event-odds cost = unique markets returned × regions; `/events` and `/sports` are free; historical = 10× and paid-only. Free Starter plan: 500 credits/month.

### Read-only odds CLI — v0.2-dev (2026-11-11, branch `agent/grok-bot/odds-cli`)

`scripts/fetch-event-odds.js` is the server-side/CLI wrapper required by the contract above. `run({argv, env, fetchImpl, now, writeFile})` is the testable entry. The real key is read only from `env.ODDS_API_KEY` and is attached to the request URL at fetch time; `sourceUrl` stored on quotes and in the snapshot is the same URL with that parameter removed. `--list` → `GET https://api.the-odds-api.com/v4/sports/basketball_nba/events`. `--event` → `GET …/events/<id>/odds?regions=…&markets=…&oddsFormat=american`. Cost guard: refuse if markets × regions > `--max-cost` (default 3). HTTP 401/422/429 exit 1 with the provider message and no file. Empty/missing `bookmakers` prints "No verified quote available" and writes no file. Snapshots stay git-ignored.

### Read-only Verify quote panel — v0.2-dev (2026-11-11, session 4, branch `agent/grok-bot/verify-quote-panel`)
**Status: BUILT; tested in a real browser against the committed MOCK snapshot (deterministic clock) and manually against one git-ignored live snapshot. Unmerged.**
- `index.html` now loads, in order, `odds-adapter.js` (`window.PropIntelAdapter`), `verify-quote.js` (`window.PropIntelVerify`), then `app.js`. Neither helper performs network requests or holds a key. The browser never calls The Odds API; fetching stays in `scripts/fetch-event-odds.js`, run by the user with `ODDS_API_KEY` in their shell.
- `openDetails()` renders a **VERIFY QUOTE · READ-ONLY** section after MARKET SNAPSHOT. The only control is a file picker (plus "Unload snapshot"). The user picks a `.snapshot.json` written by the CLI. A static page cannot list the git-ignored `data/snapshots/` directory, so there is **no auto-discovery and no relative fetch**: the file picker is the only supported path.
- `verify-quote.js` `parseSnapshotText()` accepts only the CLI shape `{meta, quotes, rejected?, quota?}` with `meta.provider = "the-odds-api"` and an ISO `meta.collectedAt`. Fails closed and loads **no** quotes when: the text is not JSON; it is a raw Odds API body (`bookmakers`, no `quotes`) or a board export; any `source_url`/`sourceUrl` contains `apiKey=`/`api_key=`/`key=`; or any quote lacks the 10 required fields, `provider_updated_at`, an American price, an Over/Under side, a numeric line, or a credential-free https `source_url`. A failed load also unloads any previous snapshot.
- `verifyRecord()` passes only the record's `player`, `market`, `side`, `line` to `PropIntelAdapter.findQuotes` (exact match; no fuzzy name, no nearest line; staleness by provider `last_update`, 30 min). The record's own `odds` / `sportsbook` (including DEMO illustration values) are never read by the panel. States: NO SNAPSHOT LOADED (no search ran), OK (fresh exact quotes: book, American price, line/side, provider update + age, collected_at, away at home, start time, key-free request URL), STALE (reason + stale exact quotes, "re-run the CLI"), UNAVAILABLE (adapter reason; no prices). A snapshot flagged `_MOCK`/`meta.mock` shows "MOCK FIXTURE · NOT REAL ODDS". If the quote's event start date (browser-local) differs from the record's game date, a warning is shown, but status is not changed (see KNOWN-ISSUES #14).
- The loaded snapshot is held in one in-memory variable for the page session and reused across cards. It is never written to records, `localStorage`, or exports. Schema `j-nba-prop-intel` 0.1 and key `j-nba-prop-intel-v0.1` unchanged; no migration.
- `nba-prop-intel.html` is now generated by `scripts/build-single-file.js` (inlines `styles.css`, `odds-adapter.js`, `verify-quote.js`, `app.js` in that order); `tests/build-sync.test.js` fails if it drifts.

Id: `odds-<eventId>-<player>-<market>-<side>-<line>`, so re-adding refreshes odds/book/time/source in place and keeps user edits. A MOCK snapshot produces `demo:true` records with `mock-` ids that can never refresh a real record.
